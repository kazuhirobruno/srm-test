## 📝 CONTEXTO DO PROJETO - MOTOR DE RECEBÍVEIS & CÂMBIO (23/07)
Olá! Estamos desenvolvendo um sistema financeiro multimoedas utilizando Java 17, Spring Boot 3.x / Spring 7.0, PostgreSQL e Flyway. Hoje concluímos 100% da camada de backend e as validações.
Aqui está o resumo do que foi implementado e está operacional:
## 1. Banco de Dados & Infraestrutura (Flyway)

* V1__infraestrutura_inicial.sql: Criação das tabelas recebiveis e taxas_cambio utilizando tipos de alta precisão (NUMERIC(18,4) e NUMERIC(18,6)).
* V2 & V3: Scripts incrementais para renomeação de colunas (valor_original), adição de campos de liquidação (valor_liquidado, moeda_liquidacao) e coluna de auditoria do relatório (cedente).
* Fusos Horários: Configurados via TIMESTAMP WITH TIME ZONE no banco mapeados para Instant no Java (Padrão UTC).

## 2. Motores de Cálculo (Design Patterns)

* Strategy Pattern: Implementado nas classes DuplicataStrategy (spread fixo de 1.5% a.m.) e ChequeStrategy (spread fixo de 2.5% a.m.) para o cálculo de Valor Presente.
* Factory Pattern: PrecificacaoFactory injeta e resolve as estratégias dinamicamente baseada no Enum do Spring Core, sem estruturas if/else.
* CambioService: Engine de câmbio que lê o banco de dados e aplica o fator de conversão de moedas apenas quando a operação for cross-currency.

## 3. Camada Transacional & Segurança (ACID Lock)

* RecebivelRepository: Implementa o método findByIdForUpdate utilizando Lock Pessimista (PESSIMISTIC_WRITE). Ele gera um SELECT ... FOR UPDATE no PostgreSQL para blindar o sistema contra cliques múltiplos e requisições simultâneas (Race Conditions).
* RecebivelService: Orquestra o cadastro, simulação em memória (sem lock) e liquidação atômica (com lock), alterando com segurança o status do título para LIQUIDADO.

## 4. APIs, Validações e Documentação (Controller)

* Todos os endpoints usam classes DTO tradicionais mapeadas com Lombok @Data, @Builder e @RequiredArgsConstructor.
* Bean Validation: Entradas blindadas com @Valid, @NotBlank, @NotNull e @Positive.
* Tratamento de Erros: Configurado via blocos explícitos de try-catch no controller com respostas semânticas atualizadas para o Spring 7.0 (404 para inexistência, 422 para violação de regras e 500 para falhas internas).
* Swagger/OpenAPI: Configurado e com as anotações descritivas em todas as rotas operacionais.

## 5. Extrato Analítico (Performance CQRS)

* RelatorioController: Implementa uma rota GET /api/v1/relatorios/extrato operando em apenas 2 camadas (Apresentação ➡️ Repositório) para alta performance.
* Query Nativa: Executa SQL Nativo dinâmico com paginação Server-Side direto no PostgreSQL, filtrando por período, cedente e moeda simultaneamente.

## 6. Testes Unitários e de Integração

* Testes criados com JUnit 5 e Mockito para as Strategies, Factory e CambioService.
* Criado o teste de integração de concorrência (RecebivelServiceConcorrenciaIT) utilizando CountDownLatch para provar a eficácia do Lock Pessimista.
